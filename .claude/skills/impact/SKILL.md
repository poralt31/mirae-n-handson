# 변경 영향도 분석

분석 대상: $ARGUMENTS

## 반드시 지킬 것
- 코드를 고치지 않는다. 파일을 만들지도 않는다. 결과는 대화로만 보고한다.
- 모든 항목에 근거를 `파일:줄번호` 로 붙인다. 줄번호는 Read · Grep 결과의 실제 줄번호만 쓴다.
- 검색으로 찾지 못한 경로를 추측으로 채우지 않는다. 의심만 되면 "추적 한계"에 적는다.
- 외부 라이브러리(`vendor/`, `node_modules/`)와 빌드 산출물(`build/`, `target/`)은 검색하지 않는다.

## 1. 대상 정의 위치 찾기
- 인자가 `파일:줄번호` 면 그 줄을 Read 해서 둘러싼 함수 · 메서드 · 프로시저 이름을 확인한다.
- 이름이면 정의 줄을 Grep 으로 찾는다. PHP `function 이름(`, Java 메서드 선언, SQL `CREATE (OR ALTER )?PROC(EDURE)? 이름`.
- 정의가 여러 곳이면(오버로드, 같은 이름 다른 파일) 모두 나열하고 사용자에게 어느 쪽인지 묻는다. 정의를 못 찾으면 멈추고 보고한다.
- `<모듈명>` 을 정한다: `legacy/item-bank-php` → `item-bank`, `legacy/assignment-thymeleaf` → `assignment`, `legacy/grade-mssql` → `grade`, `modern/` → 도메인 패키지 이름.
- 프로시저는 `legacy/grade-mssql/sql/usp_*.sql` 과 `db/mssql/init/04-procs.sql` 두 사본이 있다. 둘 다 영향 대상으로 적는다.

## 2. 호출부 역추적 (진입점에 닿을 때까지)
- 1단계: 대상 이름을 부르는 줄을 Grep 으로 찾는다(정의 줄 제외). 각 줄이 속한 함수를 Read 로 확인한다.
- 2단계 이후: 찾은 호출 함수를 다시 대상으로 삼아 반복한다. 이미 본 함수는 다시 따라가지 않는다.
- 진입점에 닿으면 멈춘다.
  - PHP: 브라우저가 직접 여는 페이지 파일(`search.php` 등) 최상위 코드, 폼 `action`
  - Spring MVC: `@GetMapping` · `@PostMapping` · `@RequestMapping` 메서드와 그 URL, 해당 Thymeleaf 템플릿
  - MS-SQL: 프로시저를 호출하는 Java 코드(`{call usp_...}` · `EXEC usp_...`) → 그 호출부의 진입점
- 인터페이스 · 상속이 끼면 구현체와 인터페이스 이름 양쪽으로 검색한다.

## 3. 테이블 영향
- 대상 함수 본문의 SQL(또는 JPA Repository · DAO 호출)에서 읽는 테이블(SELECT · JOIN · 뷰)과 쓰는 테이블(INSERT · UPDATE · DELETE · MERGE)을 뽑는다.
- 뷰를 읽으면 `db/mariadb/init/*.sql` · `db/mssql/init/*.sql` 에서 뷰 정의를 찾아 원본 테이블까지 적는다.
- 같은 테이블을 읽거나 쓰는 다른 함수를 모듈 전체에서 Grep 한다. 그중 쓰는 쪽은 따로 표시한다(수정이 데이터 모양을 바꾸면 이 함수들이 깨진다).

## 4. 관련 규칙 연결
- `docs/<모듈명>/BUSINESS-RULES.md` 가 있으면 읽고, 근거 파일:줄번호가 대상 함수 · 2단계 호출 경로 · 3단계 테이블에 걸치는 규칙 ID 를 연결한다.
- 문서가 없으면 "규칙 문서 없음"이라고만 적고, 규칙을 새로 만들지 않는다.
- 문서의 줄번호가 현재 코드와 어긋나 보이면 "규칙 문서 줄번호 불일치"로 표시한다.

## 5. 출력 형식
1. **영향받는 화면 · URL** — 화면 또는 URL / 진입 파일:줄번호
2. **호출 경로** — `진입점(파일:줄) → 함수(파일:줄) → … → 대상 함수(파일:줄)` 한 줄에 하나
3. **영향받는 테이블** — 테이블 / 대상 함수의 읽기 · 쓰기 여부 / 같은 테이블을 쓰는 다른 함수(파일:줄번호)
4. **관련 규칙 ID** — 규칙 ID / 규칙 한 줄 / 연결 근거
5. **수정 전에 확보할 테스트 케이스** — 케이스 / 입력(URL · 파라미터) / 지켜야 할 동작 / 관련 규칙 ID
   - 호출 경로마다 최소 1개, 관련 규칙마다 최소 1개. 경계값 · 빈값 · 기본 정렬처럼 규칙이 갈리는 입력을 우선한다.
   - `characterization/tests/<item-bank|assignment|grade>.test.js` 에 이미 있는 케이스는 "기존"으로 표시하고, 없으면 "추가 필요"로 표시한다.
6. **추적 한계** — 검색으로 확정하지 못한 경로와 그 이유

## 추적 한계로 적을 것 (예)
- PHP: 변수 함수 호출(`$fn()`), `call_user_func`, 변수로 조립한 `include` · `require` 경로
- Java: 리플렉션, 이름을 문자열로 넘기는 호출, 인터페이스 구현체가 여러 개인 경우
- SQL: `EXEC(@sql)` · `sp_executesql` 동적 SQL, 문자열로 조립한 테이블 · 프로시저 이름
- 모듈 밖에서 부르는 경우(배치, 다른 모듈의 같은 DB 직접 접근). `itembank` DB 는 `php` · `thymeleaf` · `modern` 이 함께 쓴다.
